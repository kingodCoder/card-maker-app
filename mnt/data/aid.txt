# 1. OBJECTIF FINAL (ce que tu veux atteindre)

À la fin, ton application doit permettre :

1. **Choix du format de carte AVANT l’édition** (comme Canva)
2. **Ouverture d’un éditeur plein écran**, inspiré du mockup
3. **Éditeur Fabric.js fonctionnel**

   * Texte, formes, images
   * Couleurs, arrondis, opacité
   * Undo / Redo
   * Calques
4. **Templates de cartes**

   * Un template de base (celui de la carte élève fournie)
   * Templates sauvegardés
5. **Création de cartes à partir d’un template**
6. **Stockage local robuste (IndexedDB)**
7. **Dashboard**

   * Affichage max 100 cartes
   * Pagination
   * Corbeille (30 jours)
   * Suppression définitive (90 jours)
8. **Page Paramètres**

   * Durées, limites, nettoyage auto

# 4. RÔLE DE CHAQUE PAGE (CLÉ DU SUCCÈS)

## 🔹 CreateCard.tsx (AVANT l’éditeur)

**Rôle :**

* Choix du format :

  * Carte élève (PVC)
  * Badge
  * Carte carrée
  * Format personnalisé
* Choix :

  * Nouveau template
  * À partir d’un template existant

**Ce que CreateCard NE DOIT PAS faire :**
❌ Aucune logique Fabric
❌ Aucun canvas

➡️ **Il redirige uniquement vers `/card-editor`**

---

## 🔹 CardEditor.tsx (PLEIN ÉCRAN)

**Rôle :**

* Monter l’éditeur Canva-like
* Charger :

  * un template
  * ou une carte existante
* Bloquer le reste de l’UI

```tsx
<EditorLayout
  templateId={...}
  cardId={...}
  onClose={() => navigate(-1)}
/>
```

---

## 🔹 EditorLayout.tsx (CŒUR DU MOCKUP)

Correspond **exactement à l’image fournie** :

* Top bar (File / Resize / Download)
* Sidebar gauche
* Panneau contextuel
* Zone canvas centrée

👉 **Aucune logique métier ici**
👉 Il orchestre les composants

---

## 🔹 useFabricEditor.ts (PIÈCE MAÎTRESSE)

**Une seule source de vérité**

```ts

addRect()
addCircle()
addImage()
setFillColor()
setRadius()
undo()
redo()
exportPNG()
exportPDF()
loadFromJSON()
toJSON()
```

➡️ **Aucun composant n’accède directement à fabric.Canvas**
